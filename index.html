Docker Container & RAM Optimization

DOCKER ACTIVE
Nama Container: osrm-backend-indonesia
Metode Routing: CH (Contraction Hierarchies)
Penggunaan RAM Server: 1.2 GB / 8.0 GB
Strategi RAM Optimization:
  • Memuat data peta menggunakan flag `--mmap` untuk menghemat alokasi memori heap virtual.
  • Menggunakan algoritma *Multi-Level Dijkstra (MLD)* untuk pembaruan waktu tempuh dinamis tanpa re-kalkulasi graf utama.
  • Menyimpan cache segment jalan tersering di buffer memori L1/L2 container.

Kesesuaian Kompetensi Developer GIS OSRM

Fastwork Requirements Map

Bagaimana pilar keterampilan yang diminta dalam proyek ekosistem superapp & GIS dipetakan di program simulator ini:

1. Pemrosesan Data OSM

Eksekusi run command server asli (`osrm-extract`, `osrm-partition`, `osrm-customize`) disimulasikan lengkap dengan visualisasi output terminal saat data peta indonesia.osm.pbf di-extract.

2. Custom Scripting LUA Profiles

Dilengkapi code-editor script LUA interaktif untuk memodifikasi kecepatan motor (motorcycle profile - diizinkan masuk gang lebar < 2m) dan mobil (car profile - jalan tol diizinkan, gang diblokir).

3. Optimasi Server & RAM

Menyediakan visualisasi RAM Monitor yang secara realtime mendeteksi lonjakan memori heap server Linux saat pipeline OSRM berjalan, serta log penjelasan metode caching MLD.

4. Integrasi Backend & API

Simulasi matang integrasi map Leaflet dengan project-osrm.org API untuk rute nyata jalan Jakarta, query JSON matriks jarak NxN (Distance Matrix API `/table`), dan callback transaksi.
